# Technical debt and known risks

This is the register of known bugs, likely bugs, fidelity gaps and technical
debt in the port and its PsyZ fork. It was compiled on 2026-11-12 from a
read-only audit of `src/main`, `src/overlays`, `include`, `src/port`, `tools`,
CI and `third_party/psyz`, plus the open items left by the DuckStation
comparison work.

Each entry has an ID, a severity and a location, and says how to fix it. When
you fix something, delete its entry in the same commit. When you find a bug,
check whether the same pattern occurs elsewhere and record that too.

Severity:

- **High**: can visibly break the game, lose data or stop it from starting
  for some players.
- **Medium**: wrong behaviour in a narrow case, undefined behaviour that
  happens to work today, or debt that is actively hiding bugs.
- **Low**: cleanup, robustness or a diagnostic-only problem.

Entries marked *(speculative)* are plausible from reading the code but have
not been reproduced.

## 3. Fidelity gaps against the console

These are measured against the modified DuckStation (`tools/port/duckstation.py`, built as `tools/port/DUCKSTATION.md` describes).
Game logic and 1x rendering already match, and every one-pad scenario (attract, all menus with and without a save, garage, emblem editor, Time Attack, Extra Trial, the full Grand Prix) enters each mode on DuckStation's field with the same FrameCounter and rand. What remains:

| ID | Where | Gap |
| --- | --- | --- |
| F1 | Versus (2 pads) | After the movie skip the title frame starts one field late, and the offset stays −1 from then on; FrameCounter is one off from mode 1/57, so the VS race seed differs. The pause frame ends late in its field for an unknown reason. Reference runs with two pads need `DSLEAD=0` in the DuckStation script. |
| F5 | Memory card | DuckStation shifts its port alternation once in the splash polling loop (around field 727). This has no visible effect, but the rule is unknown. |
| F6 | Audio | Sequenced title and menu music starts 343 samples (7.5 ms) early. The port's 60 Hz sequencer ticks run 0.375 field ahead, a phase the console sets during its own BIOS boot and exe load, which the port does not model; the only fix found so far would be a fitted start offset. Race XA music starts about 35 ms early; this is a weak match that needs confirming. |
| F7 | CD seeks | DuckStation adds seeded 0.5–1 ms jitter to each seek; the port uses a fixed 0.75 ms. |
| F8 | JogCon | The motor-command echo in the pad packet arrives 1–2 fields earlier than on DuckStation. This changes the force-feedback pattern slightly, but not steering. |
| F9 | NTSC mode | The NTSC switch is the PAL game at 60 Hz, not the Japanese release. The splash length, display-on frame and the PAL full-screen clear stay PAL by design (`docs/ARCHITECTURE.md`). The PAL release also retuned 34 car records (the first car of each manufacturer: gear-4 speed, top speed, target frames), so NTSC timing races those cars with PAL data; the Japanese disc itself is not supported (`docs/REGIONS.md`). |
| F10 | Frame interpolation | A face that is new in a frame is placed by the motion of the paired vertices next to it, which can shear it: in the attract sweep along a car (frame 2740, 1x and 4x) the rear wing coming into view is drawn as a skewed plate for one field. The same sweep scores 4–6% unexplained pixels, most of it the car's texture moving farther than the metric's reach. Outlines of a wall entering the view (no pose in the frame before) float a pixel or two above its edge (race frame 6842, also in HEAD). Thin lines that remain in the seam scan are thin geometry (poles, gantries) and a light texel column at a near wall's edge (chase frame 3292, also in HEAD). Cuts, level-of-detail switches, near-plane crossings and newly visible faces are handled by holding the previous frame or by snapping to paired neighbours, not by a true midpoint. The fixed tables in `sdl3_gpu.c` (pending ghosts, edges, field entries) are sized for one race frame per batch and drop entries silently when exceeded *(speculative)*. Headless runs present no midpoints (paced or not) unless frames are captured, so headless frame-time numbers include drawing the midpoint, not presenting it. |
| F11 | Widescreen | The squeeze also applies to native VRAM. StoreImage/MoveImage read-backs of the display buffers therefore see squeezed pixels, and 1x loses horizontal resolution. The double buffers are found by a VRAM layout rule. Widescreen exists only on SDL_GPU. |
