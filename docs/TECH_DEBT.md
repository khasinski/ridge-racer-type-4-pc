# Technical debt and known risks

This is the register of known bugs, likely bugs, fidelity gaps and technical
debt in the port and its PsyZ fork. It was compiled on 2026-11-12 from a
read-only audit of `src/main`, `src/overlays`, `include`, `src/port`, `tools`,
CI and `third_party/psyz`, plus the open items left by the DuckStation
comparison work.

Each entry has an ID, a severity and a location, and says how to fix it. When
you fix something, delete its entry in the same commit. When you find a bug,
check whether the same pattern occurs elsewhere and record that too.

Severity:

- **High**: can visibly break the game, lose data or stop it from starting
  for some players.
- **Medium**: wrong behaviour in a narrow case, undefined behaviour that
  happens to work today, or debt that is actively hiding bugs.
- **Low**: cleanup, robustness or a diagnostic-only problem.

Entries marked *(speculative)* are plausible from reading the code but have
not been reproduced.

## 3. Fidelity gaps against the console

These are measured against the modified DuckStation (`tools/port/duckstation.py`, built as `tools/port/DUCKSTATION.md` describes). Since 2026-11-19 the reference is its exact timing (`REGTEST_EXACT=1`, the default of `duckstation.py`: the interpreter, an interrupt or DMA event at its clock, on the recompiler's instruction costs), where the recompiler ran events at the end of the block being executed; values marked [rec], [mark], [exc] or [trace] before that date were measured on the recompiler, whose costs are the same (`DUCKSTATION.md` lists the comparison) but whose events land up to a block late. Against it 26 of the 27 `ds_compare.py` scenarios (with `ta-full` and `vs-full`, F13, all but `vs-slot2-only`; the six `ta-course*` ones race Time Attack on the courses no other scenario loads: 1, 2, 3, 4, 6 and 7) and the four `ds_frames.py` ones (the attract with port 1 empty on DuckStation too, `REGTEST_PAD1_TYPE=None`: the port's headless run has no controller there, and an empty port's vblank handler is 3782 clocks shorter, F16) match in every field. Against the recompiler's references 15 matched: its boot put SsStart's timer 1909 clocks off (the BIOS's boot 717 later, the SPU clear's two vblanks inside its DMA exceptions, the ROM bzero's 30 exceptions without the instruction refetch), so other blanks fell into the timer's exceptions.
Game logic and 1x rendering already match. With one card (`PSYZ_CARD_UNPLUG=2`), the regression scripts replayed there and RR4_AUTODRIVE's input replayed from the same build's run (`tools/port/ds_frames.py`, its lines read at the same moment as the port's vsyncs of that number), the attract (12000 fields, no controller on either side: `REGTEST_PAD1_TYPE=None`, as the port's unscripted run; libpad's exchange with an empty port 1 is 3782 clocks shorter, with a pad in port 2 refusing 0x43 2194, `LIBPAD_*_SAVED_CYCLES`, the vblank exception within 100 clocks of DuckStation's for a digital pad, a DUAL SHOCK, a pad in port 2 and none), Time Attack (6600), Versus (7000) and the Grand Prix (12600) match DuckStation's mode, FrameCounter, rand and race state in every field. ## 5. Tests, CI and releases

Automated game runs (scans, captures, frame-time and memory runs) go
through `tools/port/run_capped.sh`, headless (`PSYZ_HEADLESS=1` or `gpu`,
`SDL_AUDIODRIVER=dummy`). At most `RR4_RUN_SLOTS` (default 2) capped runs
execute at once machine-wide; the others wait. It kills the game when its
physical footprint, which on macOS includes GPU memory that `ps` and RSS do
not show, passes `RR4_MEM_LIMIT_MB` (default 6000), and `RR4_MEM_LOG`
records the footprint over the run. A GPU memory leak once took runs past
100 GB; if a run is killed, find the leak instead of raising the limit.
